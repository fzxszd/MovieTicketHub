# Feature Specification: 用户收藏与跨设备同步

**Feature Branch**: `未创建（未启用 Git 扩展）`

**Created**: 2026-09-25

**Status**: Draft

**Input**: User description: "登录用户可以收藏电影，收藏数据与账号绑定并在不同会话和设备之间同步。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 收藏和取消收藏电影 (Priority: P1)

登录用户可以在电影列表或详情中收藏、取消收藏，并立即看到明确状态；游客尝试收藏时先完成登录。

**Why this priority**: 收藏既是用户保存兴趣电影的基本能力，也是后续个性化推荐的主要信号。

**Independent Test**: 登录后收藏一部电影并在收藏列表看到它，再取消收藏并确认移除；重复操作不会产生重复记录。

**Acceptance Scenarios**:

1. **Given** 用户已登录且电影未收藏，**When** 点击收藏，**Then** 电影进入该账号收藏并显示已收藏状态。
2. **Given** 电影已经收藏，**When** 用户取消收藏，**Then** 电影从该账号收藏移除并显示未收藏状态。
3. **Given** 用户未登录，**When** 尝试收藏，**Then** 系统要求登录、保留电影上下文，但不创建匿名收藏或自动收藏。
4. **Given** 用户快速重复点击收藏，**When** 请求处理，**Then** 最终状态与最后一次明确操作一致，且不存在重复收藏记录。

---

### User Story 2 - 查看账号收藏列表 (Priority: P1)

用户可以查看当前账号的全部收藏，打开电影详情，并看到加载、空数据和错误状态。

**Why this priority**: 收藏必须能被找回和管理，才能真正帮助用户组织观影兴趣。

**Independent Test**: 为账号准备多部收藏，验证列表只包含当前账号内容、无重复且可以进入正确电影详情。

**Acceptance Scenarios**:

1. **Given** 当前账号有收藏，**When** 打开收藏页，**Then** 系统展示去重后的电影及最新可用资料。
2. **Given** 当前账号没有收藏，**When** 打开收藏页，**Then** 显示明确空状态和浏览电影入口。
3. **Given** 另一账号在同一设备登录，**When** 打开收藏页，**Then** 不显示上一账号的收藏或短暂闪现其缓存。

---

### User Story 3 - 跨会话和设备同步 (Priority: P2)

用户在一台设备修改收藏后，使用同一账号重新登录或在另一台设备登录，能够获得一致的收藏结果。

**Why this priority**: 账号绑定的收藏必须由服务端权威保存，否则无法可靠支持推荐和跨设备体验。

**Independent Test**: 设备 A 收藏与取消电影，设备 B 同账号同步后得到相同集合；账号 C 不受影响。

**Acceptance Scenarios**:

1. **Given** 设备 A 已成功收藏电影，**When** 同一账号在设备 B 同步，**Then** 设备 B 显示该收藏。
2. **Given** 设备 A 已成功取消收藏，**When** 设备 B 下一次同步，**Then** 该电影被移除，不因旧缓存重新出现。
3. **Given** 两台设备离线修改同一电影后恢复网络，**When** 同步完成，**Then** 系统按最后一个被服务端接受的明确操作得到单一结果，并向两台设备收敛。
4. **Given** 同步暂时失败，**When** 用户继续使用应用，**Then** 本地状态标记为待同步、提供重试，并且不会冒充已被服务端确认。

---

### User Story 4 - 离线管理收藏 (Priority: P3)

已登录且曾建立有效会话的用户在暂时离线时仍可查看本地收藏并进行修改，恢复网络后安全同步。

**Why this priority**: 移动网络并不稳定，离线体验能够减少用户操作丢失，但不能破坏服务端权威性。

**Independent Test**: 断网后执行收藏和取消，确认显示待同步；恢复网络后服务端和另一设备得到相同最终状态。

**Acceptance Scenarios**:

1. **Given** 用户离线且本地具有该账号缓存，**When** 查看收藏页，**Then** 系统展示缓存并明确标识离线状态。
2. **Given** 用户离线修改收藏，**When** 操作保存，**Then** 系统记录账号、电影、目标状态和操作顺序，显示待同步。
3. **Given** 会话已经失效，**When** 恢复网络准备同步，**Then** 系统要求重新登录，且不能把操作同步到错误账号。

### Edge Cases

- 电影资料被下架但仍在收藏中时，保留收藏记录并显示不可用说明，不能静默改成其他电影。
- 相同电影从列表、详情和推荐区域同时操作时，所有界面最终显示同一状态。
- 同步请求重复、超时或响应丢失时，服务端不得产生重复收藏。
- 用户退出或切换账号时，待同步操作必须保持账号隔离，不得由下一个账号上传。
- 服务端拒绝某条操作时，界面必须回到权威状态并说明未能保存。
- 初次登录且没有本地缓存时，同步失败不得显示其他账号或匿名收藏。
- 收藏变化触发推荐更新时，取消收藏也必须被后续推荐计算感知。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 收藏和取消收藏 MUST 要求有效登录身份，并绑定当前账号与稳定电影标识。
- **FR-002**: 游客尝试收藏时 MUST 先登录，系统不得创建匿名收藏或登录后自动执行收藏。
- **FR-003**: 用户 MUST 能从电影列表、详情和推荐入口查看并切换同一收藏状态。
- **FR-004**: 收藏添加和移除 MUST 幂等；同一账号同一电影最多存在一个当前收藏状态。
- **FR-005**: 系统 MUST 明确显示提交中、已确认、待同步和失败状态，避免把本地操作冒充服务端成功。
- **FR-006**: 用户 MUST 能查看当前账号的去重收藏列表、明确空状态和加载/错误状态。
- **FR-007**: 收藏列表中的电影 MUST 使用稳定电影标识，并尽可能显示最新资料；下架电影需保留标识与不可用说明。
- **FR-008**: 收藏的权威最终状态 MUST 存储在服务端，并只允许经过授权的所属账号读写。
- **FR-009**: 同一账号在不同会话和设备同步后 MUST 收敛到相同收藏集合。
- **FR-010**: 对同一电影的冲突操作 MUST 按服务端接受的明确操作顺序决定最终状态，并把结果返回所有设备。
- **FR-011**: 离线操作 MUST 记录账号、电影、目标状态和本地顺序，恢复网络后按顺序安全重试。
- **FR-012**: 重复同步、网络重试和响应丢失 MUST 不产生重复收藏或反复翻转状态。
- **FR-013**: 同步被拒绝时 MUST 恢复权威状态、保留可理解错误并允许用户重试有效操作。
- **FR-014**: 会话失效时 MUST 暂停同步并要求重新认证；不得把待同步操作转移给其他账号。
- **FR-015**: 退出和账号切换 MUST 清除当前界面的私有收藏状态，并防止上一账号缓存闪现。
- **FR-016**: 收藏添加和取消 MUST 都能触发后续推荐数据更新，但推荐算法本身不属于本功能。
- **FR-017**: 同步载荷和日志不得包含密码、原始会话令牌或其他账号不需要的敏感数据。

### Key Entities

- **收藏状态**: 某账号与某电影之间当前是否收藏的唯一关系，包含权威更新时间。
- **收藏操作**: 用户明确的添加或移除意图，包含账号、电影、目标状态、顺序和同步状态。
- **收藏电影快照**: 用于离线展示的非权威电影资料副本，始终关联稳定电影标识。
- **同步状态**: 本地与服务端之间的已同步、待同步、同步中或失败状态，不代表登录身份。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在正常网络下，95% 的收藏或取消操作在 2 秒内显示服务端确认状态或明确的处理中状态。
- **SC-002**: 对 100 次重复点击和请求重试测试，同一账号同一电影产生重复收藏记录的次数为 0。
- **SC-003**: 同一账号两台设备在同步完成后的收藏集合一致率达到 100%。
- **SC-004**: 不同账号在同一设备或不同设备上的收藏泄露次数为 0。
- **SC-005**: 离线添加、离线取消、冲突操作和会话失效四类测试均能收敛到一个可解释的权威状态，通过率为 100%。
- **SC-006**: 至少 90% 的测试用户能在 30 秒内找到收藏列表并打开一部已收藏电影。
- **SC-007**: 收藏为空、电影下架、网络失败和初次无缓存场景均显示明确状态或下一步操作，空白无反馈次数为 0。

## Assumptions

- 用户身份和会话由 `001-account-authentication` 提供，服务端可以从会话确定账号而不是信任客户端邮箱。
- 电影具有跨页面稳定且不可混淆的标识。
- 离线收藏只对已登录且设备上存在有效账号上下文的用户开放。
- 冲突采用最后一个被服务端接受的明确目标状态，而不是依赖设备本地时间。
- 本功能不包含收藏文件夹、标签、公开收藏榜、好友分享和推荐算法实现。
