# Feature Specification: 账号认证与会话

**Feature Branch**: `未创建（未启用 Git 扩展）`

**Created**: 2026-09-25

**Status**: Draft

**Input**: User description: "完善电影购票平台的账号认证功能，包括注册、登录、会话恢复、退出登录，以及对收藏、选座和购票操作的登录限制。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 注册普通用户账号 (Priority: P1)

一名尚未拥有账号的访客使用用户名、邮箱和密码注册普通用户账号，以便使用收藏、选座和购票功能。

**Why this priority**: 账号是所有个性化功能和交易功能识别用户身份的基础。

**Independent Test**: 使用未注册邮箱提交有效注册信息，可以创建账号并进入已登录状态；不依赖收藏、选座或购票功能即可验证。

**Acceptance Scenarios**:

1. **Given** 访客提供有效的用户名、未注册邮箱、一致且符合长度要求的密码，**When** 提交注册，**Then** 系统创建唯一账号、建立有效会话，并向用户确认注册成功。
2. **Given** 任一必填字段为空，**When** 提交注册，**Then** 系统不创建账号，并明确指出需要补充的字段。
3. **Given** 邮箱格式无效，**When** 提交注册，**Then** 系统不创建账号，并提示输入有效邮箱。
4. **Given** 密码不符合长度要求或两次密码不一致，**When** 提交注册，**Then** 系统不创建账号，并显示对应的可纠正提示。
5. **Given** 邮箱已经关联现有账号，**When** 再次提交注册，**Then** 系统不创建重复账号，并提示该邮箱已注册。

### User Story 2 - 登录并恢复会话 (Priority: P1)

已有账号的用户使用邮箱和密码登录。登录成功后，用户关闭并重新打开应用时，只要会话仍然有效，就可以继续使用账号而无需重复输入凭据。

**Why this priority**: 登录和可靠的会话恢复是用户使用收藏、选座和购票能力的必要入口。

**Independent Test**: 使用预置账号登录，重新打开应用后仍显示为同一已登录用户，即可独立验证该旅程。

**Acceptance Scenarios**:

1. **Given** 用户提供有效的注册邮箱和正确密码，**When** 提交登录，**Then** 系统建立会话并进入已登录状态。
2. **Given** 用户提交错误邮箱或密码，**When** 登录被拒绝，**Then** 系统显示不暴露账号是否存在的统一凭据错误提示，并允许再次尝试。
3. **Given** 网络不可用或服务暂时不可达，**When** 用户尝试登录，**Then** 系统保留已填写邮箱、隐藏密码内容，并提供明确的网络错误与重试入口。
4. **Given** 用户具有仍然有效的会话，**When** 关闭并重新打开应用，**Then** 系统恢复同一用户的登录状态，无需重新输入密码。
5. **Given** 已保存会话已过期或被撤销，**When** 应用尝试恢复会话，**Then** 系统安全地回到未登录状态，并提示用户重新登录。

---

### User Story 3 - 浏览与受保护操作 (Priority: P2)

未登录访客可以浏览电影；当访客尝试收藏、选座或购票时，系统要求先登录，登录成功后能够继续原先的操作流程。

**Why this priority**: 公开浏览降低使用门槛，同时保证个性化数据和交易操作绑定到明确账号。

**Independent Test**: 未登录时浏览电影，然后尝试收藏任意电影，系统要求登录且没有以匿名身份写入收藏，即可独立验证。

**Acceptance Scenarios**:

1. **Given** 用户未登录，**When** 浏览电影列表或电影详情，**Then** 系统允许继续浏览。
2. **Given** 用户未登录，**When** 尝试收藏电影、选择座位或进入购票确认，**Then** 系统在执行受保护操作前要求登录，且不产生匿名收藏、锁座或订单。
3. **Given** 用户因受保护操作进入登录流程，**When** 登录成功，**Then** 系统返回原来的业务上下文，并允许用户主动继续该操作。
4. **Given** 用户取消登录或登录失败，**When** 返回浏览界面，**Then** 系统保持未登录状态，且不会执行原受保护操作。
5. **Given** 用户是游客，或已登录但没有足够收藏，**When** 查看电影推荐区域，**Then** 系统展示热门或正在上映的非个性化内容，并明确说明当前不是基于收藏的推荐。
6. **Given** 已登录用户拥有收藏且个性化推荐可用，**When** 查看推荐区域，**Then** 系统显示当前账号的个性化结果，并标注“根据你的收藏推荐”或含义等同的来源说明。
7. **Given** 个性化推荐服务暂时失败，**When** 推荐区域仍有可用电影数据，**Then** 系统切换到非个性化备用内容、说明暂时无法生成个性化推荐并提供重试入口。

---

### User Story 4 - 主动退出登录 (Priority: P3)

已登录用户可以主动退出账号，使当前设备不再访问其个人收藏、推荐和订单信息。

**Why this priority**: 退出能力保护共享设备上的账号与交易隐私，但不阻挡首次注册和登录的核心价值。

**Independent Test**: 已登录用户执行退出，重新打开应用后保持未登录，并且受保护操作再次要求登录，即可独立验证。

**Acceptance Scenarios**:

1. **Given** 用户处于已登录状态，**When** 确认退出登录，**Then** 系统终止本地会话、清除敏感认证信息并返回登录页面；用户仍可选择以访客身份浏览。
2. **Given** 用户已经退出，**When** 重新打开应用，**Then** 系统不自动恢复刚才的账号会话。
3. **Given** 用户已经退出，**When** 尝试访问上一个账号的收藏、推荐或订单，**Then** 系统不展示账号私有数据并要求重新登录。

### Edge Cases

- 注册邮箱前后包含空格或字母大小写不同时，系统在判断邮箱唯一性前进行一致化处理，避免创建语义相同的重复账号。
- 用户名仅由空白字符组成，或长度超出允许范围时，系统拒绝注册并显示用户名规则。
- 密码位于允许长度的边界值时，系统按同一规则处理注册与提示，不出现前后端判断不一致。
- 用户连续快速点击注册或登录时，系统只处理一次有效提交，不创建重复账号或并行会话。
- 登录请求正在处理时网络中断，系统不得显示登录成功，并允许用户安全重试。
- 应用在会话恢复过程中被关闭或进入后台，下一次启动仍能得到明确且一致的登录状态。
- 会话在用户执行收藏、选座或购票的过程中失效时，系统阻止受保护操作，要求重新登录，并避免产生归属不明的数据。
- 另一用户在同一设备登录后，不得看到上一账号的收藏、推荐、订单或其他私有缓存。
- 多次失败登录触发安全保护时，系统给出可理解的稍后重试提示，但不暴露目标邮箱是否存在。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 允许访客使用用户名、邮箱、密码和确认密码注册普通用户账号。
- **FR-002**: 系统 MUST 将用户名、邮箱、密码和确认密码视为注册必填项，并在提交前后保持一致的校验结果。
- **FR-003**: 用户名 MUST 在去除首尾空格后包含 2 至 30 个可见字符；不符合规则时系统 MUST 提供明确提示。
- **FR-004**: 系统 MUST 验证邮箱具有可接受的邮箱格式，并以忽略首尾空格和字母大小写差异的方式判断邮箱唯一性。
- **FR-005**: 密码 MUST 包含 8 至 64 个字符；确认密码 MUST 与密码完全一致。
- **FR-006**: 当邮箱已经注册时，系统 MUST 阻止创建第二个账号，并明确提示该邮箱已注册。
- **FR-007**: 注册成功后，系统 MUST 建立该用户的有效登录会话并确认成功；重复提交不得创建多个账号。
- **FR-008**: 系统 MUST 允许已有用户使用注册邮箱和密码登录。
- **FR-009**: 对不存在的邮箱和错误密码，系统 MUST 使用统一的无效凭据提示，不得通过登录错误暴露账号是否存在。
- **FR-010**: 登录或注册请求进行期间，系统 MUST 显示处理中状态并阻止重复提交。
- **FR-011**: 网络或服务错误 MUST 与凭据错误区分展示，并为可恢复错误提供重试入口。
- **FR-012**: 系统 MUST 在应用重新启动后恢复仍然有效的用户会话，且不得要求用户重新输入密码。
- **FR-013**: 当会话过期、被撤销或无法继续使用时，系统 MUST 清除失效会话、切换到未登录状态，并要求用户重新登录。
- **FR-014**: 系统 MUST 允许未登录访客浏览电影列表、搜索结果和电影详情等公开内容。
- **FR-015**: 收藏、获取个性化推荐、选座和购票 MUST 要求有效登录身份；未登录状态不得创建账号归属不明的收藏、座位占用或订单。
- **FR-016**: 当受保护操作触发登录时，系统 MUST 保留其来源上下文；登录成功后用户 MUST 能返回并主动继续原操作。
- **FR-017**: 系统 MUST 允许已登录用户主动退出，并在退出后终止本地会话、清除敏感认证信息、阻止访问此前账号的私有数据并返回登录页面；登录页面 MUST 保留继续以访客身份浏览的入口。
- **FR-018**: 退出登录后重新启动应用，系统 MUST 保持未登录状态，直至用户再次成功登录。
- **FR-019**: 所有密码输入 MUST 默认隐藏；系统不得在用户可见错误、诊断信息或其他非认证用途的数据中回显密码。
- **FR-020**: 系统 MUST 对同一规范邮箱或来源在 15 分钟内累计 5 次失败登录实施 15 分钟临时阻断，同时提供不暴露账号存在性的可理解反馈和剩余等待时间。
- **FR-021**: 同一设备切换账号时，系统 MUST 隔离不同账号的收藏、推荐、订单及其他私有数据。
- **FR-022**: 本功能 MUST 仅支持普通用户的邮箱密码认证；短信登录、第三方登录、找回密码、邮箱验证和管理员账号明确不在本次范围内。
- **FR-023**: 游客、收藏不足的用户或个性化推荐暂时不可用时，系统 MUST 展示热门或正在上映的非个性化备用内容；没有任何可展示电影时 MUST 显示明确空状态和重试入口，不得留下无说明空白区域或无限加载。
- **FR-024**: 推荐区域 MUST 明确标识结果来源：个性化结果显示“根据你的收藏推荐”或等同说明，备用结果显示“热门推荐”“正在上映”或等同说明；推荐失败后的备用结果 MUST 同时告知用户当前未使用个性化推荐。

### Key Entities

- **用户账号**: 代表电影购票平台中的普通用户，包含稳定的账号标识、用户名、唯一邮箱、认证状态和账号状态；密码不作为可读取的账号资料。
- **用户会话**: 代表某个账号在设备上的已验证登录状态，具有有效、过期、撤销和退出等生命周期状态，并决定受保护功能是否可访问。
- **认证尝试**: 代表一次注册、登录或会话恢复请求及其结果，用于区分成功、输入错误、凭据错误、网络失败和安全保护状态，但不得包含可读取的密码。
- **受保护操作上下文**: 代表登录前用户试图执行的收藏、选座或购票入口，用于登录成功后返回正确业务位置，不代表该操作已经执行。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在正常网络条件下，至少 90% 的首次注册测试用户能在 2 分钟内完成账号创建，且无需外部协助。
- **SC-002**: 在正常网络条件下，至少 95% 的已有账号测试用户能在 30 秒内完成登录并看到明确结果。
- **SC-003**: 对 100% 的有效会话重启测试，用户无需重新输入密码即可恢复正确账号；对 100% 的过期或已退出会话，系统不得恢复登录。
- **SC-004**: 在验收测试覆盖的所有入口中，100% 的收藏、个性化推荐、选座和购票操作在未登录时都被阻止，且不会产生匿名私有数据或交易状态。
- **SC-005**: 对重复邮箱、重复提交和大小写不同但语义相同的邮箱测试，系统创建重复账号的次数为 0。
- **SC-006**: 注册、登录、会话恢复和退出的每种成功或失败结果都在操作完成后 3 秒内向用户显示明确反馈（不计外部服务尚未返回结果的等待时间）。
- **SC-007**: 在同一设备连续使用两个测试账号时，账号间私有收藏、推荐和订单数据相互泄露的次数为 0。
- **SC-008**: 至少 90% 的可用性测试用户能够仅依据界面提示纠正一个无效注册字段并成功重新提交。
- **SC-009**: 在游客、无收藏、个性化推荐成功、推荐服务失败和无可用电影五类验收场景中，100% 的推荐区域都显示正确来源说明、可用内容或明确空状态，且无无限加载和无说明空白区域。

## Assumptions

- 本阶段只有普通购票用户这一种账号角色，用户名作为展示名称使用，不要求全局唯一；邮箱是登录标识并且必须唯一。
- 密码采用 8 至 64 个字符的长度规则，本阶段不额外强制大小写字母、数字或特殊字符组合。
- 有效会话持续到用户主动退出、会话过期或被服务端撤销；具体有效期属于后续计划中的安全配置，但不得破坏重新打开应用时的有效会话恢复。
- 注册成功即视为账号可用，本阶段不要求邮箱验证。
- 注册、登录和首次会话建立需要可访问的账号服务；公开电影浏览不以登录为前提。
- 登录成功后返回原业务上下文，但收藏、锁座或购票等原操作不会在用户不知情的情况下自动执行。
- 短信登录、第三方登录、找回密码、管理员账号和账号注销不属于本次功能。
