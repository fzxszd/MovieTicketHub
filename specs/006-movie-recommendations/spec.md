# Feature Specification: 基于收藏的个性化电影推荐

**Feature Branch**: `未创建（未启用 Git 扩展）`

**Created**: 2026-09-25

**Status**: Draft

**Input**: User description: "根据当前账号收藏的电影为用户推荐可能感兴趣的电影，并在没有足够收藏时提供有用的非个性化内容。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 获得基于收藏的推荐 (Priority: P1)

已登录且拥有收藏的用户可以看到与其收藏偏好相关、当前可浏览的电影，并清楚知道推荐来自自己的收藏。

**Why this priority**: 这是该功能的核心价值，帮助用户从大量电影中更快发现感兴趣的内容。

**Independent Test**: 为账号准备具有明确类型或主题特征的收藏，生成推荐后验证结果与收藏相关、排除不可用电影，并标注推荐来源。

**Acceptance Scenarios**:

1. **Given** 当前账号拥有足够收藏且推荐可用，**When** 打开推荐区域，**Then** 系统展示去重结果并标注“根据你的收藏推荐”或等同说明。
2. **Given** 用户点击推荐电影，**When** 进入详情，**Then** 展示对应电影且不改变收藏状态。
3. **Given** 推荐候选包含已收藏、已购买或不可用电影，**When** 结果展示，**Then** 按既定规则排除或明确标识，不冒充新发现内容。

---

### User Story 2 - 理解推荐原因 (Priority: P2)

用户可以看到简短、真实的推荐原因，例如与某部收藏电影类型相似，而不是无法解释的排序。

**Why this priority**: 可解释性增强信任，并满足项目宪章对推荐来源透明的要求。

**Independent Test**: 检查每个个性化推荐都有至少一个来自当前账号收藏或电影特征的真实原因，且不会泄露其他用户数据。

**Acceptance Scenarios**:

1. **Given** 推荐由某些收藏偏好产生，**When** 用户查看推荐卡片或详情，**Then** 系统提供至少一个简短且与实际信号一致的原因。
2. **Given** 推荐原因无法可靠生成，**When** 展示电影，**Then** 系统使用诚实的通用标签，不编造用户偏好或具体收藏关联。
3. **Given** 两个不同账号具有不同收藏，**When** 分别查看推荐，**Then** 原因和结果只使用各自账号的数据。

---

### User Story 3 - 收藏变化后刷新推荐 (Priority: P2)

用户收藏或取消收藏电影后，下一次推荐刷新会反映变化，同时保持结果稳定、可理解，不因重复刷新随机跳动。

**Why this priority**: 推荐必须真正响应用户选择，否则用户无法控制个性化结果。

**Independent Test**: 记录推荐结果，添加和取消具有明显特征的收藏后刷新，验证结果与原因相应变化；不改变收藏时重复刷新保持稳定。

**Acceptance Scenarios**:

1. **Given** 用户新增收藏，**When** 收藏同步确认并刷新推荐，**Then** 新偏好被纳入结果和解释。
2. **Given** 用户取消收藏，**When** 后续刷新，**Then** 系统不再把该电影作为个性化依据。
3. **Given** 收藏和候选电影均未变化，**When** 用户重复刷新，**Then** 结果顺序保持足够稳定，不出现无原因的大幅随机变化。

---

### User Story 4 - 获得备用推荐 (Priority: P3)

游客、收藏不足的用户或推荐服务暂时不可用时，仍可看到热门或正在上映电影，并清楚知道这些不是个性化推荐。

**Why this priority**: 备用内容避免空白体验，同时不得把通用排序伪装成个性化结果。

**Independent Test**: 分别以游客、零收藏账号、收藏不足账号和推荐失败状态打开推荐区域，验证均显示正确来源的备用内容或明确空状态。

**Acceptance Scenarios**:

1. **Given** 用户未登录，**When** 查看首页推荐区域，**Then** 系统展示标注为热门或正在上映的非个性化内容。
2. **Given** 用户已登录但收藏不足，**When** 查看推荐，**Then** 系统展示备用内容并提示收藏电影可改善推荐。
3. **Given** 个性化推荐暂时失败，**When** 仍有可用电影，**Then** 系统展示备用内容、说明当前未使用个性化推荐并提供重试。
4. **Given** 没有任何可用电影，**When** 推荐加载完成，**Then** 显示明确空状态，不出现无限加载或无说明空白。

### Edge Cases

- 收藏全部为已下架或缺少特征的电影时，使用收藏不足的备用策略而不是编造关联。
- 账号刚切换时不得短暂显示上一账号的推荐或原因。
- 收藏同步仍在进行时，推荐要标明依据可能尚未更新，或等待权威收藏状态后再生成。
- 推荐候选重复、不同来源指向同一电影时，只展示一次。
- 推荐服务超时、部分失败或结果为空时，安全降级到通用内容并保留重试。
- 电影已购买或已收藏时，可以按产品规则降低优先级或排除，但行为必须一致且可解释。
- 广告、赞助或人工运营排序若未来加入，必须明确标识，不得伪装为收藏驱动推荐。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 个性化推荐 MUST 只面向有效登录用户，并只使用当前账号的权威收藏作为主要个性化信号。
- **FR-002**: 系统 MUST 从当前可浏览电影中产生去重推荐，不得推荐不可用或与错误账号关联的电影。
- **FR-003**: 个性化推荐区域 MUST 明确标注“根据你的收藏推荐”或含义等同的来源说明。
- **FR-004**: 每个个性化推荐 MUST 提供至少一个真实、简短且不泄露敏感信息的推荐原因；无法可靠解释时不得编造具体关联。
- **FR-005**: 推荐原因 MUST 仅引用当前账号的收藏和公开电影特征，不得泄露其他用户偏好、行为或身份。
- **FR-006**: 用户新增收藏并完成同步后，下一次推荐刷新 MUST 能纳入该偏好。
- **FR-007**: 用户取消收藏并完成同步后，后续推荐 MUST 停止使用该电影作为个性化依据。
- **FR-008**: 在收藏和候选集合不变时，重复刷新 MUST 保持稳定排序；任何变化都应来自数据或规则变化而非无意义随机数。
- **FR-009**: 系统 MUST 明确处理已收藏、已购买和不可用电影的排序或排除规则，并在同类情况下保持一致。
- **FR-010**: 游客、收藏不足或个性化推荐不可用时 MUST 显示热门或正在上映的非个性化备用内容。
- **FR-011**: 备用推荐 MUST 使用“热门推荐”“正在上映”或等同标签；服务失败后的备用内容还 MUST 说明当前未使用个性化推荐。
- **FR-012**: 没有任何可用电影时 MUST 显示明确空状态和重试入口，不得无限加载或展示无说明空白区域。
- **FR-013**: 收藏状态仍在同步时，系统 MUST 避免使用未确认数据冒充最新个性化结果，并向用户提供明确状态。
- **FR-014**: 推荐失败 MUST 不影响电影浏览、收藏和购票等核心功能。
- **FR-015**: 推荐结果、原因和缓存 MUST 按账号隔离；退出或切换账号时清除私有推荐状态。
- **FR-016**: 系统 MUST 记录不含个人敏感信息的推荐版本和结果质量指标，以便评估点击、收藏和购票转化。
- **FR-017**: 广告或付费排序不在本次范围；未来如加入 MUST 与个性化推荐明确区分。
- **FR-018**: 本功能不使用其他用户的私有收藏作为当前用户的直接推荐依据。

### Key Entities

- **推荐档案**: 当前账号已确认收藏所形成的偏好摘要，不包含密码、令牌或其他用户数据。
- **推荐候选**: 当前可浏览电影及其公开特征、可用状态和账号相关排除状态。
- **推荐结果**: 某次推荐中的电影、顺序、来源类型、原因和生成版本。
- **推荐原因**: 对结果来源的简短说明，关联当前账号收藏或公开电影特征。
- **备用推荐**: 在无法提供个性化结果时使用的热门或正在上映内容，必须标识为非个性化。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在正常网络下，95% 的推荐请求在 3 秒内显示个性化结果、备用内容或明确空状态。
- **SC-002**: 100% 的个性化结果具有正确来源标签，且每部推荐至少有一个真实可核对的原因或诚实通用说明。
- **SC-003**: 游客、无收藏、收藏不足、服务失败和无可用电影五类场景均有明确内容或空状态，空白无反馈次数为 0。
- **SC-004**: 在账号切换测试中，上一账号推荐结果或原因泄露次数为 0。
- **SC-005**: 收藏新增和取消同步完成后，推荐依据在下一次刷新中正确更新的比例达到 100%。
- **SC-006**: 收藏与候选数据不变时，连续 5 次刷新中前 10 个结果的集合一致率达到 100%，顺序无无原因随机变化。
- **SC-007**: 推荐服务失败时，电影浏览、收藏和购票核心流程仍可完成，阻断次数为 0。
- **SC-008**: 在至少 20 名代表性测试用户中，80% 能正确判断当前结果是个性化推荐还是通用备用内容。

## Amendment: canonical movie source

- **FR-019**: Recommendation candidates MUST be synchronized from the same Maoyan now-playing API used by the Android browse and detail flows. A recommendation item MUST retain that Maoyan `movieId`, title, and poster URL; navigating from it MUST request detail and credits with the same `movieId`.
- **SC-009**: For every recommendation item returned after a successful catalog refresh, the displayed card title and poster URL originate from Maoyan, and detail navigation uses the identical Maoyan movie ID.

## Assumptions

- 当前账号收藏由 `005-favorite-sync` 提供并已完成服务端确认。
- 电影候选包含足以支持基础相关性和解释的公开信息；缺少信息时使用备用推荐。
- 个性化推荐以收藏为主要信号，本阶段不使用浏览历史、位置、联系人或其他敏感行为画像。
- 已收藏或已购买电影默认不作为“新发现”优先推荐，但可在明确标识的继续关注场景中出现。
- 本功能不包含社交推荐、好友数据、广告竞价、付费排名和复杂实验平台。
