# Feature Specification: 影院与电影场次

**Feature Branch**: `未创建（未启用 Git 扩展）`

**Created**: 2026-09-25

**Status**: Draft

**Input**: User description: "用户可以查看影院和电影场次，选择合适的影院、日期与放映时间后进入选座。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 查看电影可用场次 (Priority: P1)

用户从电影详情进入购票流程，选择日期后查看仍可售票的影院和场次，并了解时间、影厅、语言版本与票价。

**Why this priority**: 没有准确的场次信息，用户无法进入后续选座和购票流程。

**Independent Test**: 为一部有多个影院和场次的电影打开场次页，能够按日期看到准确场次信息并排除已结束场次。

**Acceptance Scenarios**:

1. **Given** 电影存在未来可售场次，**When** 用户选择日期，**Then** 系统按影院展示放映时间、影厅、版本、基础票价和售票状态。
2. **Given** 当天部分场次已经开始或停止售票，**When** 用户查看当天场次，**Then** 这些场次被明确标记为不可选择，不会进入选座。
3. **Given** 所选日期没有场次，**When** 查询完成，**Then** 系统显示明确空状态，并允许更换日期或重试。

---

### User Story 2 - 筛选并比较影院 (Priority: P2)

用户可以根据区域、距离、票价和可用时间缩小影院范围，快速找到适合自己的场次。

**Why this priority**: 同一电影可能在多家影院上映，筛选和排序能显著降低选择成本。

**Independent Test**: 使用包含不同区域、距离和价格的测试影院，应用筛选与排序后只显示符合条件的影院且结果顺序正确。

**Acceptance Scenarios**:

1. **Given** 存在多个影院，**When** 用户选择区域和时间范围，**Then** 结果只包含同时满足条件且至少有一个可售场次的影院。
2. **Given** 用户选择按距离或最低票价排序，**When** 结果刷新，**Then** 每家影院按所选规则稳定排列。
3. **Given** 用户清除筛选，**When** 返回完整列表，**Then** 仍保留当前电影和日期上下文。

---

### User Story 3 - 选择场次进入选座 (Priority: P3)

用户确认影院和场次后进入对应影厅的选座页面，传递的电影、影院、时间、影厅和价格信息必须一致。

**Why this priority**: 这是场次浏览与座位库存之间的关键交接点，错误上下文会导致选错场次或金额。

**Independent Test**: 选择一个可售场次进入下一步，核对下一页展示的电影、影院、影厅、时间和票价均与所选场次一致。

**Acceptance Scenarios**:

1. **Given** 场次仍可售，**When** 用户选择该场次，**Then** 系统再次确认可售状态并进入对应选座上下文。
2. **Given** 场次在列表展示后变为停售或取消，**When** 用户选择，**Then** 系统阻止进入选座、说明状态变化并刷新场次。
3. **Given** 用户未登录，**When** 选择可售场次，**Then** 系统保留场次上下文并要求登录，登录后返回该场次但不自动锁座。

### Edge Cases

- 设备日期、时区或夏令时变化时，场次必须以影院所在地时间显示，并避免把未来场次误判为已结束。
- 同一影院存在相同时间但不同影厅或版本的场次时，必须能明确区分。
- 影院距离不可用时仍可按名称、区域和价格浏览，不得隐藏影院。
- 场次价格在用户查看期间变化时，进入选座前显示最新价格并要求用户确认。
- 网络中断或查询超时时保留电影、日期和筛选条件，并提供重试。
- 场次列表刷新后不得把用户导向已取消或已停售的旧场次。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 允许用户从电影详情查看该电影未来可售的影院和场次。
- **FR-002**: 系统 MUST 支持按影院所在地日期浏览场次，并默认选择最近仍有可售场次的日期。
- **FR-003**: 每个场次 MUST 显示电影、影院、影厅、开始时间、语言/放映版本、基础票价和售票状态。
- **FR-004**: 场次、票价、停售和取消状态 MUST 以后端权威数据为准，客户端缓存不得覆盖更新状态。
- **FR-005**: 已开始、已结束、已取消或已停止售票的场次 MUST 不可选择，并显示原因。
- **FR-006**: 系统 MUST 在没有场次时显示明确空状态，并允许更换日期或重试。
- **FR-007**: 用户 MUST 能按区域、可用时间范围和价格范围筛选影院场次。
- **FR-008**: 用户 MUST 能按默认推荐、距离或最低可售票价排序影院；距离不可用时 MUST 提供可理解的降级排序。
- **FR-009**: 筛选结果 MUST 只保留至少包含一个符合条件可售场次的影院。
- **FR-010**: 清除筛选 MUST 保留当前电影和日期，不得重置整个购票上下文。
- **FR-011**: 用户选择场次时，系统 MUST 在进入选座前重新确认该场次仍可售并使用最新票价。
- **FR-012**: 场次状态或价格发生变化时，系统 MUST 阻止使用旧数据继续，并向用户展示变化和刷新后的选择。
- **FR-013**: 进入选座时 MUST 传递稳定的电影、影院、影厅和场次标识，不得仅依赖可重复的显示名称或时间。
- **FR-014**: 未登录用户可以浏览影院和场次，但选择场次进入选座时 MUST 完成认证，且登录过程不得自动锁座。
- **FR-015**: 加载、成功、空数据和错误状态 MUST 明确可区分；错误状态 MUST 保留用户的日期和筛选条件。
- **FR-016**: 所有时间 MUST 明确按照影院所在地时区解释和展示。

### Key Entities

- **影院**: 提供放映服务的地点，包含稳定标识、名称、地址、区域、地理位置和营业状态。
- **影厅**: 影院内的具体放映空间，包含稳定标识、名称和座位布局引用。
- **电影场次**: 某部电影在特定影院影厅的放映安排，包含稳定标识、开始时间、版本、票价和售票状态。
- **场次查询条件**: 当前电影、日期、区域、时间范围、价格范围和排序方式的组合。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在正常网络下，95% 的场次查询在 3 秒内显示可用列表或明确空状态。
- **SC-002**: 至少 90% 的测试用户能在 60 秒内为指定电影找到并选择一个满足日期和价格条件的场次。
- **SC-003**: 对已结束、已取消和已停售场次的验收测试，进入选座的次数为 0。
- **SC-004**: 选择场次后，下一步展示的电影、影院、影厅、时间和票价与最新权威场次一致率达到 100%。
- **SC-005**: 在网络失败和无结果场景中，100% 的页面提供明确说明及可执行的更换条件或重试入口。
- **SC-006**: 对跨午夜和不同时区的场次测试，未来/已结束状态判断正确率达到 100%。

## Assumptions

- 影院和场次由平台后台维护，客户端不创建或编辑影院与排片。
- 场次按影院所在地时区展示，用户设备时区只影响辅助提示。
- 距离排序依赖可用的位置或城市信息；用户不授权位置时使用区域与名称作为降级依据。
- 票价为进入选座前的基础价格，最终订单金额仍需在订单确认阶段重新核对。
- 本功能不包含座位图、锁座、支付、优惠券和影院管理后台。
